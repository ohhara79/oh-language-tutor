# Web-only: remove terminal and TUI modes

## Context

The project currently ships three UIs:

1. **Plain terminal** (default, no flag) — `tutor/terminal.py` + `tutor/sink.py::TerminalSink`
2. **TUI** (`--tui`) — `tutor/tui.py`, a 898-line Textual app
3. **Web** (`--web`) — `tutor/web.py` + `tutor/web_sink.py`, FastAPI/HTMX/SSE on localhost

The user only uses the web UI. The terminal and TUI modes are dead code: extra files to maintain, an extra dependency (`textual`), an extra mutual-exclusivity branch in arg parsing, and three sink implementations to keep in lock-step with the `OutputSink` protocol. Dropping them shrinks the code by ~1,800 lines of source + ~1,200 lines of tests and makes the web UI the implicit default.

## Approach

Make web the only mode. Delete terminal + TUI sources, their tests, and the `--tui`/`--web` flags. Web is launched unconditionally from `main.py`. `--web-host`/`--web-port` stay (they're config, not mode selection).

### Files to delete

- `tutor/tui.py` — TUI app
- `tutor/terminal.py` — terminal-mode entry point
- `tutor/sink.py` — `TerminalSink` (only used by terminal mode)
- `tests/test_tui_app.py`
- `tests/test_tui_dispatch.py`
- `tests/test_tui_helpers.py`
- `tests/test_terminal.py`
- `tests/test_sink.py`

### Files to modify

- **`main.py`** — drop the `args.tui`/`args.web` dispatch and the `from tutor import run_terminal` import. Import `run_web` at module top and call `asyncio.run(run_web(args))` unconditionally. Keep the `KeyboardInterrupt → rc=130` handling.

- **`tutor/args.py`** — remove the `--tui` and `--web` flags (lines 76–84) and the mutex check on lines 97–98. Update the prog description if it mentions modes. Keep `--web-host` / `--web-port`.

- **`tutor/__init__.py`** — drop the `run_terminal` re-export. The module can shrink to just the docstring (or re-export `run_web` if a public API is desired — not required since `main.py` imports `tutor.web` directly).

- **`tutor/web.py`** — small cleanup:
  - Docstring on `run_web` (line 261): drop the `(``--web``)` qualifier since there's no mode flag any more.
  - Session-start log line (line 293): drop `mode=web` (only mode now).

- **`tests/test_args.py`** — drop `args.tui`/`args.web` assertions (lines 43–44) and the `test_tui_and_web_are_mutually_exclusive` test (lines 62–64). Other defaults / `--web-port` coverage stays.

- **`pyproject.toml`** — remove `"textual==8.2.3"` from `[project].dependencies` (line 13). After the edit, run `uv lock` so the lockfile drops `textual` and its transitive deps (`rich`, `markdown-it-py`, etc.).

- **`scripts/bladerunner.sh`**, **`scripts/srt.sh`** — drop the `--web` argument from both invocations.

- **`README.md`** — replace the `--tui` example in the "Blade Runner form" section (line 57) with the same invocation minus the flag (web is implicit), and add a one-liner that the tool serves a browser UI at `http://127.0.0.1:8000` after start. Also update the **Non-goals** section: the current bullets reference "in the terminal only" and "token streaming to terminal" (lines 106–109), which are stale once terminal mode is gone.

- **`docs/plans/2026-05-15-01-web-only.md`** — create a new plan file (per `CLAUDE.md`: plans live in `docs/plans/`, named `YYYY-MM-DD-NN-slug.md`). Mirror this plan: context, approach, file list, verification.

### Notes on shared code

These shared modules stay untouched — they're already protocol-driven and used by the web sink:

- `tutor/core.py` (`stdin_loop`)
- `tutor/types.py` (`OutputSink` protocol, dataclasses)
- `tutor/thread_pool.py`, `tutor/thread_store.py`, `tutor/tutor_store.py`
- `tutor/prompts.py`, `tutor/replay.py`, `tutor/session.py`
- `tutor/markdown_util.py` — used by `web_sink.py` for HTML rendering (was also used by the TUI, fine to keep as-is)
- `tutor/web.py`, `tutor/web_sink.py`, `tutor/templates/`, `tutor/static/`

The `OutputSink` protocol in `tutor/types.py` only has one implementation left (`WebSink`). It's still worth keeping as a protocol because `core.py` and `thread_pool.py` are typed against it; collapsing it would be a wider refactor and is out of scope.
