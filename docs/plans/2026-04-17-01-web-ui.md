# Add Web UI Mode

## Context

`oh-language-tutor` currently has two UI surfaces: a plain terminal mode (`run_terminal`, default) and a Textual TUI (`run_gui`, via `--gui`). Both consume stdin and emit explanations for a learner. The user wants a **third mode** — a browser UI — to watch the stream and drive follow-up Q&A threads from any device on the local machine (later, remotely via Cloudflare Tunnel + Access, which needs no app-level auth).

The codebase is already well-factored for a new sink: the `OutputSink` protocol (`tutor/types.py:70`) abstracts all UI events, `FollowupThreadPool` emits every state change through it, and `TerminalSink` (`tutor/sink.py`) is a minimal reference. A web sink is a straight drop-in.

**Intended outcome:** running `uv run --frozen python -m tutor ... --web` starts a local FastAPI server on `127.0.0.1:8000`, serves an HTMX+SSE single-page view, and reads stdin just like today. TUI and terminal modes are untouched.

## Confirmed choices

- Coexistence: **new mode alongside TUI** (`--web` flag).
- Stack: **FastAPI + HTMX + SSE**, server-rendered Jinja2. No Node, no build step.
- Input: **stdin pipe** (web UI is display + thread management only).
- Exposure: **localhost only**; remote access handled later by Cloudflare Tunnel + Access (no code change).

## Architecture

```
┌──────────────┐   stdin    ┌──────────────┐   SSE events   ┌──────────────┐
│  pipe/tty    │──────────▶│ stdin_loop() │─ via WebSink ─▶│  /events     │──▶ browser (HTMX)
└──────────────┘            │  (unchanged) │                 └──────────────┘
                            └──────┬───────┘                         ▲
                                   │ on_*(...)                       │
                                   ▼                                 │
                            ┌──────────────┐  POST /commands/* ┌─────┴────────┐
                            │  WebSink     │◀─────────────────▶│  FastAPI app │
                            │ (fan-out)    │                    └──────────────┘
                            └──────────────┘
```

- `stdin_loop` stays as-is; default (non-thread, no input_file) path works because web mode never redirects stdin to `/dev/tty` like the TUI does.
- `WebSink` implements `OutputSink`, fanning events to N per-subscriber `asyncio.Queue`s, each drained by one SSE connection.
- Commands (open/send/hide/delete thread, delete line) are HTTP POST; handlers call through to `FollowupThreadPool` and the authoritative state updates broadcast back over SSE.
- Multi-tab is free: all tabs subscribe to the same broadcast. Client-side filtering is implicit — OOB swaps targeting a DOM id only apply if the element exists in that tab.

## New files

### `tutor/web.py` — entry point
`async def run_web(args) -> int`. Mirrors `tutor/terminal.py:25` with these additions:
- Build FastAPI app via `build_app(ctx)` factory. `ctx` holds store, pool, sink, client, stop_event, log, filter_re, session_path, args.
- FastAPI `lifespan` (asynccontextmanager) owns startup/shutdown:
  - **Startup:** open log, build stores, `connect_with_fallback(...)` client, `FollowupThreadPool(...)`, `WebSink(log, tutor_store)`, start `stdin_task = asyncio.create_task(stdin_loop(...))`, emit initial `sink.on_thread_list(pool.list_threads())`.
  - **Shutdown (reverse):** `stop_event.set()`, cancel+await stdin_task, `await pool.close_all()`, flush pending `TutorStore.append_async` writes, `await client.__aexit__(...)`, close log.
- Run uvicorn programmatically:
  ```python
  config = uvicorn.Config(app, host=args.web_host, port=args.web_port,
                          log_level='warning', access_log=False, lifespan='on')
  server = uvicorn.Server(config)
  server.install_signal_handlers = False
  loop.add_signal_handler(signal.SIGINT, lambda: (stop_event.set(), setattr(server, 'should_exit', True)))
  await server.serve()
  ```
- Route uvicorn logs to stderr (dictConfig) so they don't interleave with the user's stdin-piped stdout.

## SSE event contract

| Event | Payload (data) | HTMX target / swap |
|---|---|---|
| `raw_line` | muted `<div>` | append to `#stream-pane` |
| `explanation` | rendered `partials/line.html` | append to `#stream-pane` |
| `thread_chunk` | `<span>text</span>` | OOB `beforeend:#msg-stream-{tid}` |
| `thread_done` | full rendered message | OOB replace `#msg-stream-{tid}` |
| `thread_list` | `partials/thread_list.html` | replace `#thread-list` innerHTML |
| `tutor_entry_removed` | empty OOB delete fragment | OOB delete `#line-{anchor_id}` |
| `error` | `partials/toast.html` | OOB append to `#toast-container` |

`data:` lines cannot contain newlines — strip `\n` from rendered HTML before emission (valid for HTML).

SSE handler:
```python
async def events(request):
    q = sink.subscribe()
    async def gen():
        try:
            yield b': hello\n\n'
            while not await request.is_disconnected():
                try: event, html = await asyncio.wait_for(q.get(), timeout=15.0)
                except TimeoutError: yield b': ping\n\n'; continue
                yield f'event: {event}\ndata: {html}\n\n'.encode()
        finally: sink.unsubscribe(q)
    return StreamingResponse(gen(), media_type='text/event-stream',
        headers={'Cache-Control': 'no-cache', 'X-Accel-Buffering': 'no'})
```

## HTTP routes

- `GET /` — server-renders `index.html` from `TutorStore.load()` + `ThreadStore.list_threads()` so reload restores state.
- `GET /events` — SSE stream (above).
- `GET /threads/{thread_id}` — renders `thread_conversation.html` via `pool.peek_meta(thread_id)`; if not active, `await pool.reopen_thread(tid)` first. Target: `#thread-conversation`.
- `POST /commands/open_thread` — body `{anchor_id}`. Server generates `thread_id = uuid4().hex`, calls `pool.open_thread(...)`. Returns rendered conversation partial.
- `POST /commands/send_message` — body `{thread_id, text}`. Appends user turn partial, spawns stream (via `pool.send_message`), SSE delivers reply chunks.
- `POST /commands/hide_thread`, `POST /commands/delete_thread`, `POST /commands/delete_tutor_entry` — delegate to pool; UI updates via SSE.

Form bodies parsed via `Annotated[str, Form()]` (ruff `FAST002` requires the `Annotated` form). Needs the `python-multipart` runtime dep.

**Same-origin / CSRF:** none. An earlier iteration checked `Origin`/`Referer` match `http://{host}:{port}` as defense-in-depth, but the browser's `Origin` can be `http://localhost:...` while the bind is `127.0.0.1:...`, producing spurious 403s on every button click. Removed — the localhost bind is the actual defense.

## Concurrency notes

- Stdin uses `asyncio.connect_read_pipe` (default); avoid uvloop to prevent edge cases.
- Uvicorn signal handlers disabled (`server.install_signal_handlers = False`); custom SIGINT handler sets `stop_event` and `server.should_exit` together.
- Uvicorn logs redirected to stderr (`log_config` → StreamHandler on `ext://sys.stderr`) so stdout stays clean for the user watching the pipe.
- `WebSink._broadcast` is non-blocking; subscribers that fall behind are logged and eventually dropped.
- Streaming chunks are plain text (no markdown parse per chunk) — matches GUI rationale in `gui.py:457-460`. Final markdown rendering happens once on `on_thread_done`.

6. Ctrl+C in the server terminal → clean exit; `state/tutor.log` contains `=== session start ===` and `=== session end ===`.

## Non-goals / risks / open items

- **Offline CDN:** HTMX/SSE scripts fetch from unpkg. If we need fully offline, vendor them. Defer.
- **Large history:** `GET /` rendering thousands of lines will slow. Defer last-N slicing + "load older" pagination.
- **Packaging:** if the project is ever built as a wheel, `tutor/templates/` and `tutor/static/` must be declared in `pyproject.toml` packaging config. Local `uv run` is unaffected.
- **Per-tab thread focus:** currently only a URL hint; tabs share server state. OK for single-user v1.
- **WebSocket alternative:** not needed — all streams are server→client. SSE is simpler and reconnects automatically.
