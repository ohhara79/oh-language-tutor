# Show Chinese pronunciation as pinyin ruby

## Context

We just shipped furigana ruby for Japanese explanations (commit `5779397`). Today, Chinese pronunciation is still shown as parenthetical pinyin plus IPA, e.g. `学习 / 學習 (xuéxí, [ɕɥěɕǐ])`. The same pedagogical problem as Japanese applies — the learner has to map syllables back to characters mentally, and characters in the 🔁 Variant rewrite or quoted in Expression/Context carry no pinyin at all. We want the same treatment for Chinese: pinyin sits directly above each character via HTML `<ruby><rt>` tags.

The rendering pipeline already passes raw HTML through unchanged (`tutor/markdown_util.py:38-41`, `| safe` in `tutor/templates/partials/line.html:6` and `tutor/templates/index.html:65`), and the Japanese change has already exercised this end-to-end — no backend, template, CSS, or JS work is needed.

## Approach

### Format (per-character ruby, IPA preserved)

For Chinese, one Han character = one syllable (with negligible exceptions like 儿化 erhua), so per-character ruby is unambiguous and matches the standard textbook convention. This is the one place where the Chinese rule deliberately differs from Japanese: Japanese mora-to-kanji splits are ambiguous, so Japanese stayed whole-word.

Vocabulary row, both scripts:
```
<ruby>学<rt>xué</rt>习<rt>xí</rt></ruby> / <ruby>學<rt>xué</rt>習<rt>xí</rt></ruby> [ɕɥěɕǐ] → 학습
```

Vocabulary row, simplified == traditional (slash dropped):
```
<ruby>你<rt>nǐ</rt>好<rt>hǎo</rt></ruby> [ni˨˩˦ xɑʊ̯˨˩˦] → 안녕하세요
```

- Each Han character gets its own `<rt>` inside one outer `<ruby>` span — the word stays a single ruby unit while pinyin sits above the correct character.
- Tone marks live on the pinyin syllable as usual (`xué`, `nǐ`). Underlying tones are preserved (e.g. 你好 stays `nǐ hǎo` in the `<rt>`s, not `ní hǎo` after sandhi).
- The parenthetical `(xuéxí, …)` is dropped. IPA stays in brackets after the word(s).
- Non-Han characters (Latin letters, digits, punctuation) sit outside `<ruby>` spans. Erhua (儿化) collapses to one `<rt>` over the two-character span, e.g. `<ruby>哪儿<rt>nǎr</rt></ruby>`.

### Scope

Pinyin ruby applies to every Han-character span anywhere in the Chinese explanation, mirroring the Japanese scope:

- 🔁 Variant row — the simplified ↔ traditional rewrite gets pinyin ruby over each character.
- 📚 Vocabulary row — both scripts get pinyin ruby; parenthetical pinyin is removed (IPA stays).
- 💡 Expression / 🎬 Context rows — any quoted Chinese phrase or word inside the target-language prose gets pinyin ruby.

The dual-script duplicate-half guard (`prompts.py:143-151`) already covers Chinese; it gets extended to mention that for Chinese the comparison is on the inner characters of the two `<ruby>` spans, matching the Japanese clause already there.
